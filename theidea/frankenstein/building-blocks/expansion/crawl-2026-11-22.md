# what the crawl added

the four fronts in `the-research-front.md` were read off the repos themselves. this note is the
same fronts read through the search and scrape keys, so the rules in the build are cited to the
specs rather than to memory. sources are linked inline; the synthesis below was drafted with
adaptionlabs' glm-5.3-flash over the scraped text and then checked against the pages.

## skills

the contract is smaller than expected: a folder with a required `SKILL.md`, frontmatter carrying
`name` and `description`, optionally `allowed-tools`, `license`, `metadata`, and optional
`scripts/`, `references/`, `assets/` directories (https://agentskills.io/home,
https://docs.claude.com/en/docs/agents-and-tools/agent-skills/overview).

the one rule that decides whether a skill works at all is that the description is the activation
matcher: it must say what the skill does **and when to use it**, or the skill never triggers. a
skill is matched by its description, not by its body, because the body is not in the context
yet.

three levels, each loaded at a different time (anthropic's own framing): metadata always,
body on activation, bundled files never in context at all, read by tool call when the file is
needed, and scripts execute without their source entering the context. the spec fixes no
numeric caps, which means the cap is the host's slice budget. ours: 500 characters for level 1,
8000 for level 2, and a bundled file read on its own call.

refusals the material supports: missing name or description; a description that does not say
when; an unscoped shell in `allowed-tools` (scope it as `bash(git)`); hardcoded model ids;
`disable-model-invocation: true` together with `user-invocable: false`, which makes a skill
neither matchable nor callable. the wild shows both csv and yaml-list forms for `allowed-tools`,
so the parser takes both and normalises.

the security rule is not in the spec and has to be ours: a skill is text a foreign author wrote
and its scripts run on the agent's computer, so a skill may not widen a permission, and a
bundled path may not climb out of the skill directory.

## teams

what the formation material agrees on, and what the roster now encodes:

- disjoint seats. two agents doing roughly the same thing is a handoff without added value, and
  every handoff is a failure point (https://www.mindstudio.ai/blog/single-agent-vs-multi-agent-team-decision-framework).
  without a responsibility matrix, agents either assume someone else covers a task or duplicate
  it, and under load they revert to generic behaviour
  (https://www.splunk.com/en_us/blog/artificial-intelligence/multi-agent-system-failures.html).
- exactly one coordinator. crewai requires a manager for the hierarchical process
  (https://docs.crewai.com/en/concepts/crews); autogen's group chat has a single speaker
  selector and a termination condition
  (https://microsoft.github.io/autogen/stable/user-guide/core-user-guide/design-patterns/group-chat.html).
  the coordinator seat must not double as a doer seat.
- refuse rather than degrade. if the roster cannot fill disjoint roles plus a coordinator, the
  card should be refused, not fielded with overlapping generalists. the topology table's `solo`
  is the legitimate cheap outcome, and multi-agent formation is only justified when the expected
  synergy beats the best single expert (https://www.alphaxiv.org/abs/2602.01011).
- review independence. the reviewer is a distinct agent with its own context; a human seat for
  team-level decisions is a first-class pattern, not a fallback
  (https://www.agno.com/blog/bring-human-review-into-multi-agent-teams).

## rails

the frameworks share a taxonomy rather than a product: input rails before the model call,
output rails after it, and tool rails around each guarded call, which are the only coverage for
mid-chain handoffs because agent-level rails fire only at chain endpoints
(https://openai.github.io/openai-agents-python/guardrails/,
https://docs.nvidia.com/nemo/guardrails/latest/index.html). execution is either parallel, where
the agent may already have spent tokens and run tools before the tripwire cancels, or blocking,
where the rail completes first.

what an output rail checks that a pre-dispatch rail cannot, because none of it exists yet at
dispatch: secrets, pii or another crew's context leaving in the answer; claims that do not match
the retrieved evidence; the tool call and arguments proposed inside the answer, before they
leave; and the side effects already executed under a parallel-mode input rail.

every rail in critter.town today fires before dispatch. that is the gap this front names, and
the reason the output rail is its own unit rather than another guardrail kind.

## holdout

beyond file permissions, four things keep a holdout unreadable to the generator: the holdout
lives outside the repo in its own store; the generator works in a sparse checkout that excludes
the validation paths (https://github.com/michaellaws/dark-factory); the harness injects the
holdout into the validator's context only at evaluation time and returns a structured verdict;
and no residual copy reaches any slice, log, trace, memory or evidence artifact the doer can
read. a generator that can read its own acceptance criteria optimises for the criteria rather
than the intent. the validator should be an agent designed to disagree, publishing a signed
verdict through the evidence scheme, because a free-text failure note is the criteria
paraphrased back.

## adaptionlabs, unblocked

the earlier note recorded this host as reachable but undocumented: every guessed path 404'd. the
docs are public at https://docs.adaptionlabs.ai/api and the base path is `/api/v1`, not `/v1`.
verified live with the key: `GET /api/v1/models` (gemma-4, glm-5.3-flash, qwen3.5-397b,
deepseek-v4-flash and others), `GET /api/v1/datasets`, `GET /api/v1/tools`,
`GET /api/v1/training-models`, and `POST /api/v1/chat/completions` in the openai shape. the
completions endpoint returns `reasoning_content` alongside `content`, and a model given a small
token budget can spend all of it on reasoning and answer with empty content, which is worth
knowing before wiring it as a provider.
